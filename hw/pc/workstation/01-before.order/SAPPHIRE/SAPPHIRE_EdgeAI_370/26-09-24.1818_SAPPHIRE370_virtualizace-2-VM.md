# SAPPHIRE Edge AI 370 — virtualizace (provoz 2+ virtuálních serverů)

Use-case na dotaz 2026-09-24: „Šlo by na tomto HW provozovat 2 virtuální servery?" Vztaženo ke konfiguraci [SAPPHIRE Edge AI 370](./26-09-23.2315_prehled-a-nezavisle-recenze.md): Ryzen AI 9 HX 370 (12C/24T), 64 GB DDR5, NVMe Gen4 SSD.

## Verdikt: ano, bez problému — a s velkou rezervou ✅

2 virtuální servery se vejdou pohodlně, reálně i víc. Limitem není CPU, ale RAM — a 64 GB je na 2 VM štědrých.

## Proč to zvládne

| Zdroj | SAPPHIRE 370 | Význam pro VM |
|---|---|---|
| CPU | 12 jader / **24 vláken** | dost na rozdělení mezi host + více VM |
| RAM | 64 GB (max 96) | **hlavní limit VM** — tady štědrý |
| Úložiště | NVMe **Gen4** SSD | rychlé virtuální disky, nízká latence |
| HW virtualizace | **AMD-V (SVM) + NPT** (nested paging) | plná hardwarová akcelerace CPU/paměti |
| Passthrough | **IOMMU (AMD-Vi)** | lze prokládat zařízení do VM |
| Nested virt. | ano | hypervisor uvnitř VM funguje |

## Hypervisory, které poběží

Všechny běžné, s plnou HW akcelerací:
- **Proxmox VE** / **KVM/QEMU** (Linux) — ideál pro „server lab"
- **Hyper-V** (Windows Pro/Server)
- **VMware Workstation**, **VirtualBox**

## Konkrétní rozdělení pro 2 servery

| | vCPU | RAM |
|---|---|---|
| VM server 1 | 4 vCPU | 16 GB |
| VM server 2 | 4 vCPU | 16 GB |
| **Host + rezerva** | zbytek z 24 vláken | **32 GB** |

- Komfortní scénář. U lehčích serverů (8 GB/VM) utáhne klidně **4–6 VM**.
- Přepis (overcommit) vCPU je běžný — 24 vláken dává velkou volnost.
- Pro tvůj typ práce (K8s node, Kafka broker, monitoring, DB…) ideální **dev/lab** stroj.

## Úložiště pro VM

- Virtuální disky na NVMe Gen4 → rychlé I/O, žádné plotny.
- Kapacitu plánuj dle VM: běžný linuxový server 20–40 GB/VM, s daty víc. Na 1 TB SSD se vejde víc VM; při náročnějších datech zvaž 2 TB (viz [výběr SSD](./SSD/26-09-24.1803_SAPPHIRE370_SSD-vyber-a-thermal-pad.md)).
- Druhý M.2 slot (2242) umožní oddělit VM úložiště od systému.

## A s Debianem to půjde? Ano — jako host i jako guest

**Debian jako hostitel (hypervisor):** ✅
- Debian + **KVM/QEMU + libvirt** je jedno z nejosvědčenějších řešení virtualizace vůbec. AMD-V (SVM) využívá KVM na jakémkoli rozumně novém kernelu.
- Alternativa: **Proxmox VE** je **postavený na Debianu** — přidá webové UI pro správu VM, snapshoty, zálohy. Pro „server lab" nejpohodlnější.
- Pro CPU virtualizaci samotnou stačí i starší kernel; ale protože HX 370 (Strix Point) je nová platforma, kvůli plné podpoře hardwaru (chipset, síť, senzory, iGPU) doporučuju **novější kernel** — buď **Debian 13 „Trixie"**, nebo Debian 12 „Bookworm" s **backports kernelem** (~6.9+). Stejná poznámka jako u [obecné kompatibility Debianu](./26-09-23.2315_prehled-a-nezavisle-recenze.md) v přehledu.
- Pozn.: pro **headless hypervisor** je grafický ovladač (amdgpu) skoro irelevantní — virtualizace nezávisí na displeji. Novější kernel je spíš pro jistotu se zbytkem hardwaru.

**Debian jako guest (samotné virtuální servery):** ✅ triviálně
- Debian VM běží na jakémkoli hypervisoru bez problému. Ideálně nainstalovat **virtio** ovladače (disk/síť) pro plný výkon — v Debianu jsou standardně.

**Shrnutí:** klidně **Debian host (KVM/libvirt nebo Proxmox) + Debian VM** — čistě opensource, plná HW akcelerace, žádná omezení pro tvůj scénář. Jediné doporučení je novější kernel kvůli novosti platformy Strix Point.

## Poctivé výhrady

1. **Jeden fyzický stroj → žádná redundance/HA.** 2 „servery" na jedné krabičce = když padne hardware, spadnou oba. Skvělé pro **dev/test/lab**, ne pro produkční vysokou dostupnost.
2. **RAM strop 96 GB** (a dál se nerozšíří). 64 GB na 2 VM stačí, ale paměťově náročné VM (velké DB, Java haldy, více K8s podů) plánuj s rozmyslem.
3. **Bez ECC** — spotřebitelská platforma ECC nepodporuje. Pro kritická serverová data by ECC bylo lepší; pro lab/dev nevadí.
4. **Jen iGPU** — žádné rozumné GPU passthrough pro těžké GPU výpočty ve VM.
5. **Souběh s ostatní zátěží** — pokud poběží VM zároveň s OBS/streamováním/vývojem, rozděl zdroje; 12C/24T + 64 GB má ale rezervu i na to.

## Souhrn

Pro **2 virtuální servery (a víc)** je SAPPHIRE 370 velmi vhodný — 24 vláken dává CPU rezervu, NVMe rychlé disky, AMD-V/IOMMU plnou virtualizační podporu. Reálný limit je **RAM (64 GB = pohodlné pro 2 VM)** a fakt, že je to **jeden stroj bez HA** — takže ideální jako **dev/lab/test** hypervisor, ne produkční HA cluster.
