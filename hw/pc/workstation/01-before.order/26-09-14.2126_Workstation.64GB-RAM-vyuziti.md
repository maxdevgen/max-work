# K čemu reálně využiješ 64 GB RAM (a proč 32 GB "tak tak stačí")

Vychází z toho, co jsi řekl: na Dell laptopu s 32 GB ti to teď "tak tak stačí" na běžnou vývojářskou práci (Visual Studio, otevřené aplikace). Nový stroj má navíc **běžet 24/7** a přibýt mu role (Docker, Claude Code, případně Windows vedle Debianu) – to jsou přesně ty věci, které 32 GB přetlačí a 64 GB dá pohodlnou rezervu.

## Kde se to reálně sečte

| Co běží | Odhad spotřeby RAM | Poznámka |
|---|---|---|
| Debian host + grafické rozhraní | ~2–4 GB | základ, běží pořád |
| Docker + pár kontejnerů (např. databáze, cache, appka) | ~4–16 GB | roste s počtem/velikostí kontejnerů, u tebe už běží na NUC14 |
| **Windows (pokud poběží jako VM vedle Debianu, ne dual-boot)** | **~16–24 GB** | Windows samotný ~4 GB, Visual Studio s velkým řešením (solution) + IntelliSense/rozšíření klidně dalších 4–8 GB, plus rezerva na plynulost |
| Claude Code (agent, vzdálené ovládání) | ~1–2 GB | nenáročné, ale běží pořád na pozadí |
| Prohlížeč s otevřenými kartami | ~4–8 GB | notoricky žere hodně, obzvlášť Chrome/Edge s víc kartami |
| Příležitostné testování lokálního LLM | ~10–30 GB | jen když zrovna testuješ, jinak 0 |
| Rezerva pro OS diskovou cache (page cache) | zbytek | "volná" RAM se nepromarní – OS ji použije jako cache, takže opakované buildy/starty kontejnerů jsou rychlejší, protože se čte z RAM, ne z disku |

Sečti si jen tu "stálou" zátěž bez Windows VM a lokálního LLM (Debian + Docker + Claude Code + prohlížeč): **~11–30 GB** – to už samo o sobě dost ukusuje z 32 GB, a pokud k tomu přidáš Windows VM (dalších 16–24 GB) nebo test LLM (dalších 10–30 GB), 32 GB rychle dojde a systém začne swapovat (odkládat na disk) – to je přesně ten moment, kdy to "začne být cítit" jako zpomalení.

## Konkrétně, jak ti 64 GB pomůže

1. **Windows a Debian současně, bez kompromisu.** Pokud poběží Windows jako virtuální stroj vedle Debianu (místo dual-bootu, kdy běží jen jedno najednou), potřebuješ dost RAM pro oba zároveň. S 64 GB si klidně necháš Windows VM s Visual Studiem otevřené a zároveň Docker kontejnery a Claude Code běžet na pozadí – nic se nemusí zavírat.
2. **Víc Docker kontejnerů najednou bez swapování.** Databáze, cache, pár mikroslužeb – s 64 GB je můžeš nechat běžet trvale (to je ostatně smysl toho "24/7" provozu), aniž bys musel řešit, co vypnout, aby se uvolnilo místo.
3. **Rezerva pro 24/7 roli i při současné interaktivní práci.** Stroj má běžet pořád na pozadí (Claude Code, kontejnery) – 64 GB dává prostor, aby tahle "trvalá" zátěž nekolidovala s tím, když si k tomu sedneš a začneš aktivně vyvíjet.
4. **Rychlejší opakované buildy a práce s Dockerem díky diskové cache.** Volná RAM není "vyhozená" – OS (Linux i Windows) ji automaticky použije jako cache pro často čtené soubory (NuGet balíčky, Docker image vrstvy, git objekty). Čím víc volné RAM, tím víc se toho vejde do cache a tím rychlejší jsou opakované operace (druhý a další build, restart kontejneru), protože se nečte znovu z (pomalejšího) disku.
5. **Možnost otestovat si lokální LLM bez nutnosti nejdřív všechno zavřít.** Jak jsme řešili dřív – větší kvantizované modely (desítky GB) se ti prostě vejdou vedle běžícího Dockeru a Windows VM, ne místo nich.
6. **Obecná rezerva proti swapování.** Tohle je asi nejdůležitější bod: když RAM dojde, OS začne odkládat data na disk (swap) a systém viditelně zpomalí – přesně ten pocit "tak tak to stačí", co znáš z Dellu. 64 GB (dvojnásobek toho, na co jsi zvyklý) dává rezervu, aby se tohle nestávalo ani při současném běhu Windows VM + Dockeru + běžné práce.

## Shrnutí

Na **holý** Debian + běžnou práci by ti možná i 32 GB dál stačilo – ale ty plánuješ přidat Docker (trvale), Windows (buď VM, nebo přepínání), 24/7 provoz na pozadí a příležitostně lokální LLM. To jsou přesně ty vrstvy navíc, které se u tebe na Dellu dnes nesčítají (Dell běží "jen" Windows + práce), ale na novém stroji ano. 64 GB tak není luxus "pro jistotu", ale realistický součet toho, co má stroj podle zadání dělat současně.
